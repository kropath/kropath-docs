# House-rules follow-up (spec docs-website.md §15)

**This file's presence switches `make lint`'s house-rules check to warn-only** (see the
`house-rules-lint` target in the `Makefile`). Its presence is temporary and load-bearing: per
spec §15, a lint check that surfaces pre-existing defects "will very likely fail on existing
pages the first time it runs... they are never left as warnings." **Delete this file once every
item below is fixed** — that re-arms `make lint` as a blocking check and closes this follow-up.

## Why these are warnings, not blockers, in this PR

Rules 1 (bare `kropath.run/` API group) and 2 (provider-prefixed kind names) were fully fixed in
this migration PR — those are mechanical, verifiable-against-the-schema fixes and there is no
reason to defer them.

What remains is exclusively rules 4 and 6: **125** internal-repository links and **108**
internal-tracker/decision citations (`ADR-####`, `KRO-####`) across **83** files, mostly
"Further reading" sections linking straight to `kropath-core` ADR docs, and inline prose citing
an ADR/ticket number as the reason a field behaves a certain way. Fixing these correctly means
rewriting each citation in the reader's own terms per the `kropath-docs-authoring` skill §1 (state
the *reason* the ADR captures, not the ADR itself) — editorial work requiring judgment per page,
not a mechanical `git mv`/regex fix. That volume is squarely what spec §15's warning-then-follow-up
path exists for.

## Scope

- 226 violations across 81 files, all rule 4 ("link to an internal kropath repository") or rule 6
  ("internal tracker/decision citation"). (Started at 233/83; 7 violations across 2 files were
  fixed directly in this PR as part of making every internal link actually resolve — htmltest has
  no warn-only exception, so those specific dangling `ADR-###`/internal-repo links had to be
  removed rather than deferred. What's left is citations embedded in prose that doesn't also
  contain a broken link, which is exactly the editorial rewrite this file defers.)
- Full, current list: `python3 scripts/check-house-rules.py content` (still runs — this file only
  changes its exit code and the `WARNING` label, not what it reports).

## How to close this out

1. For each flagged line, replace the citation with the reason it captures, stated for a reader
   who has never seen `kropath-core` (`kropath-docs-authoring` skill §1 has worked examples).
2. Re-run `python3 scripts/check-house-rules.py content` until it reports zero violations.
3. Delete this file.
4. `make lint` is blocking on house rules again from that commit on.
