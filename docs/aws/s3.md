# AWS S3 Buckets

The AWS S3 family within kropath provides abstractions for managing Amazon S3 object storage buckets. It enables platform engineers to enforce organization-wide controls such as encryption, public access blocking, and versioning mandates, while allowing application teams to provision and configure S3 buckets for their specific needs like data pipelines, log archival, and static website hosting.

## Prerequisites and Setup

While `AWSS3Bucket` resources can be created independently of compute or networking resources, the S3 family integrates with other kropath families for advanced functionality:

*   **Policy Family:** For defining granular bucket access policies using the `AWSPolicyDocument` CRD.
*   **IAM Family:** For specifying IAM roles (e.g., for cross-region replication) via the `AWSIAMRole` CRD.
*   **KMS Family:** For referencing AWS KMS keys to enable Server-Side Encryption with KMS (SSE-KMS).

## Configuration

Kropath's S3 configuration is managed through two primary Custom Resources (CRs): `AWSS3Bucket` for defining individual S3 buckets, and `AWSS3Config` for establishing organization-wide or profile-specific governance policies. These CRs leverage a robust ten-tier governance cascade to ensure compliance while providing flexibility.

### AWSS3Bucket Core Fields

The `AWSS3Bucket` Custom Resource defines the desired state of an S3 bucket. Here are its core configuration fields:

*   `configRef` (string, default: `"general-policy"`): Specifies which `AWSS3Config` profile to use for governance. If the named profile does not exist, it falls back to `"general-policy"`.
*   `nameOverride` (string): Allows overriding the bucket name derived from the naming template.
*   `deletionPolicy` (string, default: `"retain"`): Determines the behavior upon deletion of the `AWSS3Bucket` CR. Options are `"retain"` (AWS S3 bucket is preserved) or `"delete"` (AWS S3 bucket is deleted).
*   `region` (string): The AWS region where the bucket will be created. For `us-east-1`, this field should be omitted, as AWS rejects `createBucketConfiguration.locationConstraint` for this region. For other regions, it explicitly sets the `locationConstraint`.

#### Metadata and Tags

*   `tags` (map<string,string>): Custom AWS tags applied to the S3 bucket. These are merged with mandatory and default tags from `AWSKropathConfig` and `AWSS3Config`.
*   `syncedLabels` (map<string,string>): Kubernetes labels that are mirrored as AWS tags and prefixed with `kropath.run/`.
*   `syncedAnnotations` (map<string,string>): Kubernetes annotations that are mirrored to AWS resource tags and prefixed with `kropath.run/`.

#### Encryption

Controls how data is encrypted at rest within the bucket.

*   `encryption.algorithm` (string): Specifies the encryption algorithm. Options are `"AES256"` (SSE-S3) or `"aws:kms"` (SSE-KMS). Falls through to the `AWSS3Config` cascade.
*   `encryption.kmsKeyArn` (string): The ARN of the KMS key to use for SSE-KMS. Falls through to the `AWSS3Config` cascade.
*   `encryption.bucketKeyEnabled` (boolean, default: `true`): When `true` with SSE-KMS, enables S3 Bucket Keys to reduce KMS request costs. Ignored for `AES256`.

#### Public Access Blocking

*   `blockPublicAccess` (boolean, default: `true`): Controls whether public access to the bucket is blocked. Falls through to the `AWSS3Config` cascade. Setting this to `false` at the instance level only takes effect if no higher-priority mandatory governance tier enforces `true`.

#### Versioning

*   `versioning` (string): Configures object versioning for the bucket. Options are `"Enabled"` or `"Suspended"`. Falls through to the `AWSS3Config` cascade.

#### HTTPS Enforcement

*   `enforceHttpsOnly` (boolean, default: `false`): When `true`, the RGD automatically generates and applies a bucket policy statement (`DenyNonTLSAccess`) to ensure all access to the bucket is over HTTPS. This field follows the `AWSS3Config` cascade.

#### Object Ownership

*   `objectOwnership` (string, default: `"BucketOwnerEnforced"`): Specifies the object ownership setting for the bucket. Options include `"BucketOwnerEnforced"`, `"BucketOwnerPreferred"`, or `"ObjectWriter"`.

### AWSS3Config Governance Model

`AWSS3Config` CRs define per-profile governance settings for S3 buckets. These profiles are referenced by `AWSS3Bucket` instances via `spec.configRef`. Each `AWSS3Config` includes `mandatory` and `defaults` sections for governance fields:

*   **`mandatory`:** Fields set in this section enforce strict policies that cannot be overridden by `AWSS3Bucket` instances. If a `mandatory` field is set, the instance's corresponding field (if present) is ignored or validated against the mandatory setting.
*   **`defaults`:** Fields set here provide baseline configurations that `AWSS3Bucket` instances can override. They apply only when the instance's corresponding field is not explicitly set.

**Example Profiles:**

*   `general-policy`: A conservative baseline profile (e.g., `defaults.encryptionAlgorithm: "aws:kms"`, `defaults.blockPublicAccess: true`).
*   `strict`: A hardened compliance profile (e.g., `mandatory.encryptionAlgorithm: "aws:kms"`, `mandatory.blockPublicAccess: true`, `mandatory.enforceHttpsOnly: true`).
*   `public-datasets`: A profile specifically designed to allow public access for certain use cases (e.g., `mandatory.blockPublicAccess: false`).

### Ten-tier Governance Cascade

Kropath employs a ten-tier governance cascade (ADR-010, ADR-015 §5.3) to resolve effective configuration for S3 buckets. This cascade ensures that organizational-level policies take precedence, followed by profile-specific settings, and finally instance-level overrides.

The `kropath-controller` pre-merges all governance sources (from `AWSKropathConfig` and `AWSS3Config`) into `status.effectiveConfig` on the namespaced `AWSS3Config` CR. `AWSS3Bucket` RGDs read this `status.effectiveConfig` to determine the final, resolved settings.

**When to use `AWSKropathConfig.s3` vs. `AWSS3Config`:**

*   **`AWSKropathConfig.s3`:** Used for blanket, organization-wide governance that applies across *all* S3 profiles. For example, setting `AWSKropathConfig.mandatory.s3.blockPublicAccess: true` would force all S3 buckets in the organization to block public access, regardless of the `AWSS3Config` profile they use. (Levels 1-2 and 8-9 of the cascade).
*   **`AWSS3Config`:** Used for per-profile governance. For instance, a `pci` `AWSS3Config` profile might mandate a specific KMS key only for buckets using that profile, allowing other profiles more flexibility. (Levels 3-4 and 6-7 of the cascade).

**Boolean Governance Semantics (C8):** For boolean fields like `blockPublicAccess` and `enforceHttpsOnly`, `false` in a `mandatory` or `defaults` tier means "follow the next tier in the cascade" rather than explicitly disabling the control. To explicitly disable a control (e.g., allow public access when it's defaulted to blocked), a dedicated `AWSS3Config` profile must be created with `mandatory.<field>: false`, and the `AWSS3Bucket` instance must reference this profile.

## Naming Conventions

S3 bucket names must be globally unique across all AWS accounts, are 3-63 characters long, and can only contain lowercase alphanumeric characters and hyphens. They must start and end with an alphanumeric character.

Kropath's default naming template for S3 buckets is `{namespace}-{name}-{account_id}`. The `effectiveName` (the final bucket name) is derived from this template, with `spec.nameOverride` providing an escape hatch to bypass the template. The RGD automatically applies `.lowerAscii()` to the generated name to ensure compliance with S3's lowercase requirement.

### Region Handling: The `us-east-1` Special Case

When `spec.region` is set to `us-east-1` or is omitted, the `createBucketConfiguration.locationConstraint` field is explicitly omitted from the underlying ACK `Bucket` CR. This is because AWS's S3 API rejects a non-empty `locationConstraint` value for `us-east-1`. For any other region, `spec.region` will be used to set the `locationConstraint`.

## Example AWSS3Bucket Custom Resource

```yaml
apiVersion: kropath.run/v1alpha1
kind: AWSS3Bucket
metadata:
  name: my-secure-app-bucket
  namespace: data-prod
spec:
  configRef: strict # Uses the 'strict' AWSS3Config profile
  region: ap-southeast-2
  deletionPolicy: retain
  encryption:
    algorithm: "aws:kms"
    kmsKeyArn: "arn:aws:kms:ap-southeast-2:123456789012:key/some-key-id"
    bucketKeyEnabled: true
  blockPublicAccess: true
  versioning: "Enabled"
  enforceHttpsOnly: true
  objectOwnership: "BucketOwnerEnforced"
  tags:
    environment: production
    application: my-app
  syncedLabels:
    data-sensitivity: high
```

## Cross-Provider Notes

While kropath aims for a consistent experience, certain S3 features have AWS-specific nuances:

*   **Naming:** S3's global uniqueness constraint for bucket names is specific to AWS. Other cloud providers have different naming scopes.
*   **HTTPS Enforcement:** The `enforceHttpsOnly` field's mechanism of generating a `DenyNonTLSAccess` bucket policy statement is unique to AWS S3.
*   **Object Ownership:** AWS S3's `objectOwnership` controls are related to its Access Control List (ACL) deprecation path, a concept not directly mirrored in other providers.
*   **Region Handling:** The special handling of `us-east-1` for `createBucketConfiguration.locationConstraint` is an AWS S3 API-specific detail.
