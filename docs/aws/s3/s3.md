# AWS S3 Buckets

The AWS S3 family within kropath provides abstractions for managing Amazon S3 object storage buckets. It enables platform engineers to enforce organization-wide controls such as encryption, public access blocking, and versioning mandates, while allowing application teams to provision and configure S3 buckets for their specific needs like data pipelines, log archival, and static website hosting.

## Prerequisites and Setup

While `S3Bucket` resources can be created independently of compute or networking resources, the S3 family integrates with other kropath families for advanced functionality:

*   **Policy Family:** For defining granular bucket access policies using the `PolicyDocument` CRD.
*   **IAM Family:** For specifying IAM roles (e.g., for cross-region replication) via the `IAMRole` CRD.
*   **KMS Family:** For referencing AWS KMS keys to enable Server-Side Encryption with KMS (SSE-KMS).

## Configuration

Kropath's S3 configuration is managed through two resources: instances of the `S3Bucket` resource kind (which comes from a kro RGD and auto-generates its CRD) for defining individual S3 buckets, and `S3Config` custom resource instances for establishing organization-wide or profile-specific governance policies. These resources leverage a robust ten-tier governance cascade to ensure compliance while providing flexibility.

### S3Bucket Core Fields

An `S3Bucket` instance represents the desired state of an S3 bucket. Here are its core configuration fields:

*   `configRef` (string, default: `"general-policy"`): Specifies which `S3Config` profile to use for governance. If the named profile does not exist, it falls back to `"general-policy"`.
*   `nameOverride` (string): Allows overriding the bucket name derived from the naming template.
*   `deletionPolicy` (string, default: `"retain"`): Determines the behavior upon deletion of the `S3Bucket` CR. Options are `"retain"` (AWS S3 bucket is preserved) or `"delete"` (AWS S3 bucket is deleted).
*   `region` (string): The AWS region where the bucket will be created. For `us-east-1`, this field should be omitted, as AWS rejects `createBucketConfiguration.locationConstraint` for this region. For other regions, it explicitly sets the `locationConstraint`.

#### Metadata and Tags

*   `tags` (map<string,string>): Custom AWS tags applied to the S3 bucket. These are merged with mandatory and default tags from `KropathConfig` and `S3Config`.
*   `syncedLabels` (map<string,string>): Kubernetes labels that are mirrored as AWS tags and prefixed with `aws.kropath.run/`.
*   `syncedAnnotations` (map<string,string>): Kubernetes annotations that are mirrored to AWS resource tags and prefixed with `aws.kropath.run/`.

#### Encryption

Controls how data is encrypted at rest within the bucket. (Note: `S3Bucket` uses nested `encryption.*` fields, while `S3Config` profiles flatten these to camelCase fields like `encryptionAlgorithm` and `kmsKeyArn`.)

*   `encryption.algorithm` (string): Specifies the encryption algorithm. Options are `"AES256"` (SSE-S3) or `"aws:kms"` (SSE-KMS). Falls through to the `S3Config` cascade.
*   `encryption.kmsKeyArn` (string): The ARN of the KMS key to use for SSE-KMS. Falls through to the `S3Config` cascade.
*   `encryption.bucketKeyEnabled` (boolean, default: `true`): When `true` with SSE-KMS, enables S3 Bucket Keys to reduce KMS request costs. Ignored for `AES256`.

#### Public Access Blocking

*   `blockPublicAccess` (boolean, default: `true`): Controls whether public access to the bucket is blocked. Falls through to the `S3Config` cascade. Setting this to `false` at the instance level only takes effect if no higher-priority mandatory governance tier enforces `true`.

#### Versioning

*   `versioning` (string): Configures object versioning for the bucket. Options are `"Enabled"` or `"Suspended"`. Falls through to the `S3Config` cascade.

#### HTTPS Enforcement

*   `enforceHttpsOnly` (boolean, default: `false`): When `true`, the RGD automatically generates and applies a bucket policy statement (`DenyNonTLSAccess`) to ensure all access to the bucket is over HTTPS. This field follows the `S3Config` cascade.
    
    **Phase 1 behavior:** In this phase, the `DenyNonTLSAccess` statement is injected directly into `spec.policy` on the underlying ACK `Bucket` CR. This means kropath owns the bucket policy field entirely; any external bucket policy configuration on the same bucket will be overwritten or conflict.
    
    **Phase 2 (aws-s3-06, deferred):** Future phases will transition this to `bucketPolicyRef` composition, where bucket policies are managed as separate `PolicyDocument` CRs, enabling co-existence of the `enforceHttpsOnly` requirement with other user-defined policies.

#### Object Ownership

*   `objectOwnership` (string, default: `"BucketOwnerEnforced"`): Specifies the object ownership setting for the bucket. Options include `"BucketOwnerEnforced"`, `"BucketOwnerPreferred"`, or `"ObjectWriter"`.

#### Server Access Logging

*   `logging.enabled` (boolean): Enables S3 server access logging for the bucket.
*   `logging.targetBucket` (string): Name of the bucket that receives the access logs.
*   `logging.targetPrefix` (string): Key prefix applied to delivered log objects.

These fields follow the `S3Config` cascade (`loggingEnabled`, `logDeliveryBucket`, and
`loggingTargetPrefix` in the profile tiers).

**AWS constraint — same account, same Region.** S3 server access logging requires the target bucket
to be owned by the **same AWS account** as the source bucket and to be in the **same Region**. A
target bucket in a different account is rejected. To centralize S3 access records into a bucket in
another account, use CloudTrail S3 data events, which do support a cross-account destination.

#### Lifecycle Rules

`lifecycle` (array) is an instance-only field — it has no governance cascade. Each rule supports:

| Field | Purpose |
|---|---|
| `id` | Rule identifier |
| `status` | `Enabled` or `Disabled` (default `Enabled`) |
| `filter.prefix` | Restrict the rule to a key prefix |
| `filter.tag.key` / `filter.tag.value` | Restrict the rule to objects carrying a tag |
| `transitions[].days` / `transitions[].storageClass` | Move objects to another storage class after N days |
| `expiration.days` | Delete objects after N days |
| `expiration.expiredObjectDeleteMarker` | Clean up expired delete markers |
| `noncurrentVersionExpiration.noncurrentDays` | Delete non-current versions after N days |
| `noncurrentVersionTransitions[]` | Transition non-current versions by storage class |
| `abortIncompleteMultipartUpload.daysAfterInitiation` | Abort stalled multipart uploads |

```yaml
spec:
  lifecycle:
    - id: expire-raw-input
      status: Enabled
      filter:
        prefix: "raw/"
      transitions:
        - days: 30
          storageClass: STANDARD_IA
      expiration:
        days: 90
      abortIncompleteMultipartUpload:
        daysAfterInitiation: 7
```

#### Event Notifications

`notification` (instance-only, no governance cascade) publishes object events to a Lambda function,
an SQS queue, or an SNS topic:

*   `notification.lambdaConfigurations[]` — each takes `id`, `lambdaFunctionARN`, `events[]`, and
    an optional `filter.key.filterRules[]`
*   `notification.sqsConfigurations[]` — same shape, with `queueARN`
*   `notification.snsConfigurations[]` — same shape, with `topicARN`

Each `filterRules` entry is a `{name, value}` pair where `name` is `prefix` or `suffix`.

```yaml
spec:
  notification:
    lambdaConfigurations:
      - id: process-uploads
        lambdaFunctionARN: "arn:aws:lambda:us-east-1:123456789012:function:process-upload"
        events:
          - "s3:ObjectCreated:*"
        filter:
          key:
            filterRules:
              - name: prefix
                value: "incoming/"
              - name: suffix
                value: ".json"
```

> **Not supported: EventBridge notifications.** There is no `eventBridgeConfiguration` under
> `notification`, so routing S3 events to EventBridge cannot be expressed on the `S3Bucket` CR.
> Enable it out of band with
> `aws s3api put-bucket-notification-configuration --notification-configuration '{"EventBridgeConfiguration": {}}'`,
> and re-check it after any change to `spec.notification` — ACK owns that configuration and a
> reconcile can overwrite the out-of-band setting.

#### Other Instance-Only Fields

*   `cors` (array): CORS rules (`id`, `allowedMethods`, `allowedOrigins`, `allowedHeaders`,
    `exposeHeaders`, `maxAgeSeconds`).
*   `intelligentTiering` (array): S3 Intelligent-Tiering configurations.
*   `transferAcceleration` (boolean, default `false`): Enables S3 Transfer Acceleration.
*   `objectLockEnabled` / `objectLockMode` / `objectLockRetentionDays`: S3 Object Lock settings.
*   `bucketPolicyRef` (string): Name of a `PolicyDocument` CR supplying the bucket policy. Note that
    `enforceHttpsOnly` currently writes directly into the bucket policy field (see
    [HTTPS Enforcement](#https-enforcement)), so the two conflict until Phase 2 lands.

### S3Config Governance Model

`S3Config` CRs define per-profile governance settings for S3 buckets. These profiles are referenced by `S3Bucket` instances via `spec.configRef`. Each `S3Config` includes `mandatory` and `defaults` sections for governance fields:

*   **`mandatory`:** Fields set in this section enforce strict policies that cannot be overridden by `S3Bucket` instances. If a `mandatory` field is set, the instance's corresponding field (if present) is ignored or validated against the mandatory setting.
*   **`defaults`:** Fields set here provide baseline configurations that `S3Bucket` instances can override. They apply only when the instance's corresponding field is not explicitly set.

**Example Profiles:**

*   `general-policy`: A conservative baseline profile (e.g., `defaults.encryptionAlgorithm: "aws:kms"`, `defaults.blockPublicAccess: true`).
*   `strict`: A hardened compliance profile (e.g., `mandatory.encryptionAlgorithm: "aws:kms"`, `mandatory.blockPublicAccess: true`, `mandatory.enforceHttpsOnly: true`).
*   `public-datasets`: A profile specifically designed to allow public access for certain use cases (e.g., `mandatory.blockPublicAccess: false`).

### Ten-tier Governance Cascade

Kropath employs a ten-tier governance cascade (ADR-010, ADR-015 §5.3) to resolve effective configuration for S3 buckets. This cascade ensures that organizational-level policies take precedence, followed by profile-specific settings, and finally instance-level overrides.

The `kropath-controller` pre-merges all governance sources (from `KropathConfig` and `S3Config`) into `status.effectiveConfig` on the namespaced `S3Config` CR. `S3Bucket` RGDs read this `status.effectiveConfig` to determine the final, resolved settings.

**When to use `KropathConfig.s3` vs. `S3Config`:**

*   **`KropathConfig.s3`:** Used for blanket, organization-wide governance that applies across *all* S3 profiles. For example, setting `KropathConfig.mandatory.s3.blockPublicAccess: true` would force all S3 buckets in the organization to block public access, regardless of the `S3Config` profile they use. (Levels 1-2 and 8-9 of the cascade).
*   **`S3Config`:** Used for per-profile governance. For instance, a `pci` `S3Config` profile might mandate a specific KMS key only for buckets using that profile, allowing other profiles more flexibility. (Levels 3-4 and 6-7 of the cascade).

**Boolean Governance Semantics (C8):** For boolean fields like `blockPublicAccess` and `enforceHttpsOnly`, `false` in a `mandatory` or `defaults` tier means "follow the next tier in the cascade" rather than explicitly disabling the control. To explicitly disable a control (e.g., allow public access when it's defaulted to blocked), a dedicated `S3Config` profile must be created with `mandatory.<field>: false`, and the `S3Bucket` instance must reference this profile.

## Naming Conventions

S3 bucket names must be globally unique across all AWS accounts, are 3-63 characters long, and can only contain lowercase alphanumeric characters and hyphens. They must start and end with an alphanumeric character.

Kropath's default naming template for S3 buckets is `{namespace}-{name}-{account_id}`. The `effectiveName` (the final bucket name) is derived from this template, with `spec.nameOverride` providing an escape hatch to bypass the template. The RGD automatically applies `.lowerAscii()` to the generated name to ensure compliance with S3's lowercase requirement.

### Dynamic Tag Fields in Naming Templates

S3 naming templates support `{tag.fieldName}` placeholders that allow you to embed tag values directly into bucket names. For example, a template like `{tag.environment}-{tag.application}-{name}` would derive the bucket name from tags defined in `spec.tags`, `spec.syncedLabels`, or `spec.syncedAnnotations`, combined with the CR name.

Tag values are resolved in a cascading order: mandatory tags from governance config, then instance-level tags, then default tags. If a referenced tag does not exist, the naming template validation reports `status.namingStatus: invalid-unresolved-tokens`.

**Example:**

```yaml
spec:
  tags:
    environment: production
    application: data-pipeline
  # With a naming template: "{tag.environment}-{tag.application}-bucket"
  # effectiveName = "production-data-pipeline-bucket"
```

For detailed information on dynamic tag field syntax, tag resolution order, provider constraints, and best practices, see [Dynamic Tag Fields in Naming Templates](../../resources/naming-template-dynamic-tags.md).

### Region Handling: The `us-east-1` Special Case

When `spec.region` is set to `us-east-1` or is omitted, the `createBucketConfiguration.locationConstraint` field is explicitly omitted from the underlying ACK `Bucket` CR. This is because AWS's S3 API rejects a non-empty `locationConstraint` value for `us-east-1`. For any other region, `spec.region` will be used to set the `locationConstraint`.

## Example S3Bucket Resource Instance

```yaml
apiVersion: aws.kropath.run/v1alpha1
kind: S3Bucket
metadata:
  name: my-secure-app-bucket
  namespace: data-prod
spec:
  configRef: strict # Uses the 'strict' S3Config profile
  region: ap-southeast-2
  deletionPolicy: retain
  encryption:
    algorithm: "aws:kms"
    kmsKeyArn: "arn:aws:kms:ap-southeast-2:123456789012:key/some-key-id"
    bucketKeyEnabled: true
  blockPublicAccess: true
  versioning: "Enabled"
  enforceHttpsOnly: true
  objectOwnership: "BucketOwnerEnforced"
  tags:
    environment: production
    application: my-app
  syncedLabels:
    data-sensitivity: high
```

## Cross-Provider Notes

While kropath aims for a consistent experience, certain S3 features have AWS-specific nuances:

*   **Naming:** S3's global uniqueness constraint for bucket names is specific to AWS. Other cloud providers have different naming scopes.
*   **HTTPS Enforcement:** The `enforceHttpsOnly` field's mechanism of generating a `DenyNonTLSAccess` bucket policy statement is unique to AWS S3.
*   **Object Ownership:** AWS S3's `objectOwnership` controls are related to its Access Control List (ACL) deprecation path, a concept not directly mirrored in other providers.
*   **Region Handling:** The special handling of `us-east-1` for `createBucketConfiguration.locationConstraint` is an AWS S3 API-specific detail.
